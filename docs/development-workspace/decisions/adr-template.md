# ADR template

Use this working template when a durable engineering choice needs its rationale
and lifecycle recorded. A decision record does not make a proposal canonical or
prove its implementation.

## Status

Use `proposed`, `accepted`, `superseded`, or `abandoned`; link the replacement
when a decision is superseded.

## Context, decision, and consequences

State the verified problem and constraints; distinguish observed implementation
from assumptions. Describe the selected boundary, meaningful alternatives, and
security, operational, migration, or follow-up consequences. Link supporting
evidence and the implementation commit when one was examined.
