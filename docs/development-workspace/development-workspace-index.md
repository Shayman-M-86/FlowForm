# Development workspace

The Development Workspace holds work in progress: questions, options, evidence,
plans, trial results, migration records, and debt that still needs a decision.
It provides a place to preserve useful uncertainty without presenting it as
accepted behaviour or architecture.

## Boundary and lifecycle

Project Knowledge owns maintained understanding of the current system. A
workspace item may inform that collection, but it does not change it merely by
being written or marked complete. Distil an accepted, implementation-backed
outcome into Project Knowledge when appropriate; otherwise keep the document
here, revise it as work changes, or retain it in the archive for traceability.

## Work categories

Early possibilities begin in [[ideas-index|Engineering ideas]]. Research and
[[investigations-index|Engineering investigations]] collect evidence or resolve
specific questions. [[experiments-index|Engineering experiments]] record bounded
trials. [[decisions-index|Engineering decisions]] captures choices and their
status, while [[planning-index|Engineering planning]] coordinates intended
execution. [[migrations-index|Engineering migrations]] tracks bounded changes
between states, and [[technical-debt-index|Technical debt workspace]] holds
known liabilities. [[archive-index|Engineering archive]] retains inactive
material that remains useful for historical reasoning.
